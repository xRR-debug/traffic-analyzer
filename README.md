# TrafficAnalyzer

Анализатор дампов трафика абонента для техподдержки провайдера. Открываете дамп
(`tcpdump`, `.pcap`, `.pcapng`) — программа объясняет, что происходит с
соединениями: блокировки ТСПУ/РКН, поддельные RST, «заморозка» на 16 КБ,
подмена DNS, VPN и прокси у абонента, где рвётся соединение и кто владелец
адреса.

Изначально сделан для helpdesk провайдера MARYNONET (AS39709), но собственная
сеть задаётся в настройках — подходит любому провайдеру.

- **Windows** — окно (Dear ImGui + DirectX 11) и консольное меню, один `.exe`.
- **macOS** (Apple Silicon и Intel) — окно (GLFW + OpenGL 3) и консоль, сборка через CMake.

## Что умеет

- **Анализ блокировок** — находит характерные признаки ограничений на пути и
  объясняет каждый простыми словами, с советом, что сказать абоненту.
- **Анализ VPN/прокси** — определяет туннели, прокси и обходчики DPI у абонента,
  выставляет вердикт «ВЕРОЯТНО / ВОЗМОЖНО» с перечнем признаков.
- **Временной профиль соединения** — водопад пакетов одного TCP-соединения:
  рукопожатие, TLS, паузы, ретрансмиты, где именно остановились данные.
- **Проверка РКН** — ручная проверка домена или IP по открытой базе
  [cheburcheck.ru](https://cheburcheck.ru): реестр, блокировки, результаты
  проверок доступности.
- **Сетевые инструменты** — трассировка, геопроверка по RTT, захват трафика,
  проверка портов снаружи, сканер портов, UDP-пробы VPN-протоколов, поиск узла
  ТСПУ, проверка честности DNS, тест 16 КБ, владелец адреса.
- **Сравнение двух дампов** — «до/после» или «у нас / с другой сети».
- **Отчёт** — текстовый отчёт можно сохранить или скопировать в тикет.

## Окно программы

Файлы можно перетащить в окно. Меню: **Файл**, **Анализ**, **Инструменты**,
**Вид**. На панели инструментов — «Открыть…», «VPN / прокси», «Блокировки»,
«Резолв ASN», «Сравнить…».

| Вкладка | Что в ней |
|---|---|
| **Обзор** | Карточки VPN и «TCP и DNS»; «Признаки блокировок» — таблица причин с подсказками (что это и что ответить абоненту); заблокированные SNI и IP; «Куда уходит трафик» — топ адресов. |
| **Соединения** | Все потоки: адрес, имя, страна/ASN, порты, состояние, объём, график скорости (sparkline — ровные «полки» выдают шейпер). Фильтр, сортировка. По правой кнопке — временной профиль, копирование IP/имени, фильтр Wireshark, фильтр по адресу, анализ блокировок для адреса, владелец IP, проверка в cheburcheck. |
| **Профиль соединения** | Водопад пакетов одного TCP-соединения. Сверху — список адресов с поиском (заблокированные и проблемные вверху), затем список соединений выбранного адреса; кнопки «← Пред. / След. →». |
| **Проверка РКН** | Ручная проверка домена или IP в cheburcheck.ru: вердикт, записи реестра, статус и результаты проверок доступности. Можно скопировать отчёт. |
| **Журнал** | Текстовый отчёт анализа: копировать, сохранить, очистить. |
| **Инструменты** | «Кому принадлежит IP / домен» прямо в окне; запуск консольных инструментов и список запущенных. |
| **Настройки** | Оформление (темы, свои обои или встроенная картинка, анимации); пороги детекторов, порты, своя сеть; перечитать `analyzer.ini`. |

Интерфейс учитывает масштаб экрана (DPI).

## Консольные режимы

Консольное меню — `TrafficAnalyzer.exe --console`. Режимы 3–13 и 0 можно
запустить сразу: `--tool N` (так их запускает и окно — каждый в своей консоли).
В меню клавиша `Delete` (на Mac — `L`) включает запись отчёта режимов 1 и 2 в файл.

| № | Режим |
|---|---|
| 1 | Анализ VPN / прокси по дампу |
| 2 | Анализ блокировок и проблем с соединением (можно задать один адрес) |
| 3 | Трассировка |
| 4 | Геопроверка по RTT — правдоподобна ли заявленная страна адреса |
| 5 | Захват трафика в `.pcap` (Npcap / libpcap) |
| 6 | Проверка порта снаружи через Globalping |
| 7 | Сканер TCP-портов |
| 8 | UDP-пробы рукопожатий VPN-протоколов |
| 9 | Поиск узла ТСПУ, который блокирует по SNI (DPI Locator) |
| 0 / 10 | Сравнение двух дампов |
| 11 | Честность DNS (подмена ответов) |
| 12 | Тест «16 КБ» на зарубежный хостинг |
| 13 | Кому принадлежит IP / домен |

## Что распознаётся в дампе

### Блокировки и проблемы соединения

| Код | Признак |
|---|---|
| `HTTP_STUB` | HTTP-заглушка о блокировке вместо сайта |
| `TLS_RST_FORGED` | Поддельный RST — инъекция DPI (по TTL, времени, поведению сервера) |
| `TLS_RST` | RST сразу после ClientHello без явных признаков подделки |
| `TLS_DROP` | Молчаливый дроп после ClientHello — почерк блокировки по SNI. В текстовом дампе без содержимого — первый сегмент данных на :443 без ответа (если к этому адресу ничего больше не работало) |
| `TCP16` | Обрыв после ~16 КБ — ограничение к зарубежным хостингам |
| `SYN_DROP` | Нет ответа на SYN — блокировка по IP или недоступен сервер/маршрут |
| `UDP_DROP` | UDP без ответа — QUIC или VPN-протокол режется |

Также:

- **Аномалии DNS** — нет ответа, подмена на частные адреса или адреса-заглушки.
- **Обходчики DPI у абонента** — дробление ClientHello (split) и похожие приёмы.

### VPN и прокси

- TLS-клиенты по отпечатку **JA4**.
- **VLESS / Reality** и похожие маскирующиеся протоколы.
- Долгие туннельные потоки с равномерным трафиком.
- Известные порты VPN (UDP и TCP) и прокси; база **IP2Proxy LITE**, если подключена.
  Порт засчитывается в полную силу, только если соединение открыл абонент и через
  него прошло от 50 КБ; прокси-порты и UDP 8443/1935 — только к хостингу (не CDN).
- Итог по баллам: от 3 — «ВЕРОЯТНО», от 1 — «ВОЗМОЖНО».

### Прочее

- Графики скорости потоков: ровная «полка» выдаёт ограничение скорости (шейпер).
- Состояния TCP: норма, нет ответа, сброс, трафик в одну сторону, начало не в дампе.

## Входные данные

- Текстовый вывод `tcpdump`.
- `.pcap` и `.pcapng`.
- Пары файлов `*_in` / `*_out` (входящий и исходящий трафик отдельно)
  склеиваются автоматически.

## Внешние сервисы и приватность

Дамп анализируется локально. Наружу уходят только адреса, и только в описанных
ниже случаях.

| Сервис | Для чего | Когда |
|---|---|---|
| ip-api.com, ipwho.is, ipapi.is | Страна, ASN и владелец адреса | Автоматически при `auto_resolve=1` (по умолчанию); отключается `auto_resolve=0`, тогда — только по кнопке «Резолв ASN» |
| Globalping | Проверка порта и трассировка снаружи | Только в режимах, где вы это запускаете |
| cheburcheck.ru | Проверка домена или IP по реестру и базам блокировок | **Только вручную**: вкладка «Проверка РКН» или пункт контекстного меню. Автоматически ничего не отправляется |
| IP2Proxy LITE | Признаки VPN/прокси/хостинга у адреса | Локальный файл базы, сеть не нужна |

API cheburcheck.ru не документирован официально и может измениться.

## Настройки — analyzer.ini

Скопируйте `analyzer.ini.example` в `analyzer.ini` рядом с программой.
Без файла действуют значения по умолчанию. Файл можно перечитать из окна:
«Настройки» → «Перечитать analyzer.ini».

| Секция | Ключи |
|---|---|
| `[general]` | `auto_resolve` — автоматический резолв гео/ASN; `ip2proxy_db` — путь к `.BIN` базе IP2Proxy LITE |
| `[thresholds]` | `tail_ms`, `freeze_min_kb`, `freeze_max_kb`, `freeze_silence_ms`, `freeze_later_pkts`, `tspu_min_syn`, `split_min_conns`, `shape_cap`, `flow_score_cap`, `long_flow_*` |
| `[ports]` | `vpn_udp_ports`, `vpn_tcp_ports`, `proxy_ports`, `scan_*_ports` |
| `[isp]` | `own_isp_org`, `own_isp_asn` — своя сеть: её адреса не считаются подозрительными |
| `[vpn_whitelist]` | `vpn_whitelist_domains`, `vpn_whitelist_asn` — белый список VPN (Google/YouTube, Википедия, VK/MAX, Госуслуги, Яндекс, банки…): адрес в списке по AS или по DNS из дампа (одного SNI мало) не даёт баллов VPN, проблемы соединения по нему проверяются; сигнатуры WireGuard/OpenVPN срабатывают. `+` в начале значения — дописать к стандартному списку |

Каждый ключ описан в комментариях `analyzer.ini.example`.

База IP2Proxy LITE скачивается на [lite.ip2location.com](https://lite.ip2location.com)
после регистрации (ZIP распаковать, путь указать в `ip2proxy_db`). Обновлять её
стоит раз в месяц.

## Сборка

### Windows

Нужно: Visual Studio 2022 или новее с компонентом «Разработка классических
приложений на C++», Windows 10 SDK.

Файлов Npcap в репозитории нет (их лицензия не разрешает распространение),
перед первой сборкой положите их сами:

- **Npcap SDK** — скачайте с [npcap.com](https://npcap.com/#download)
  («Npcap SDK») и распакуйте в `npcap-sdk/`, чтобы получилось
  `npcap-sdk/Include/pcap.h` и `npcap-sdk/Lib/x64/wpcap.lib`;
- **установщик Npcap** — скачайте с того же сайта и сохраните как
  `redist/npcap-installer.exe`; он встраивается в `.exe` через `npcap.rc`.

Затем:

1. Откройте `TrafficAnalyzer.vcxproj`.
2. Выберите `Release | x64` и соберите.

`wpcap.dll` загружается отложенно: без установленного Npcap программа работает,
недоступен только захват (режим 5).

### macOS

```bash
brew install cmake glfw
```

```bash
cmake -B build
```

```bash
cmake --build build -j
```

- Бэкенды ImGui (GLFW и OpenGL 3) скачиваются при первом `cmake -B build`
  из репозитория ocornut/imgui той же ревизии, что и ядро в `gui/imgui`.
- Зависимости: libcurl и libpcap из системы, GLFW из Homebrew; фреймворки
  OpenGL, ImageIO, CoreGraphics, CoreFoundation.
- Рядом с программой копируются `anime_bg.jpg` и `analyzer.ini.example`.
- Для захвата (режим 5) нужен доступ к `/dev/bpf*`: запуск через `sudo` или
  ChmodBPF (ставится вместе с Wireshark).

## Запуск

```bash
TrafficAnalyzer.exe
```

```bash
TrafficAnalyzer.exe dump_in.pcap dump_out.pcap
```

```bash
TrafficAnalyzer.exe --console
```

```bash
TrafficAnalyzer.exe --console dump.pcap
```

```bash
TrafficAnalyzer.exe --tool 9 --log
```

| Параметры | Что происходит |
|---|---|
| без параметров | Открывается окно |
| `[дампы]` | Окно с открытыми дампами |
| `--console [дамп]` | Консольное меню |
| `--tool N` | Сразу запустить режим N (3–13, 0) в своей консоли |
| `--log` | Сразу включить запись отчёта в файл |

На macOS: `./build/TrafficAnalyzer`, `./build/TrafficAnalyzer --console`.
